常见问题

下面这些几乎都是在实际使用中踩出来的，按「最常遇到」排序。每条都先讲原因再给办法， 不写「请重试」这种没信息量的话。

外接屏的亮度滑块没反应，显示「亮度不可控」

按这个顺序排查，大多数情况在第一步就能解决：

  1. 先在显示器自己的按键菜单里找找有没有 DDC/CI 开关。 不少显示器（尤其是一些型号的出厂默认值）把这个功能关着，关着的时候一律不应答。 打开之后回应用点「重新检测 DDC」。
  2. 换一根线试试。 通过某些 USB-C 扩展坞、KVM 切换器、HDMI 转接头的链路可能会把 I²C 通道吃掉。 直连（比如显示器原装的 DP 线）通常就好了。
  3. 跑一次 --ddc-test 看具体卡在哪：
    终端
    "/Applications/Display Master.app/Contents/MacOS/DisplayMaster" --ddc-test
    它会打印读数 → 写入 → 复读 → 恢复的全过程。如果读得到、写不进去，是时序问题（本应用已按 MonitorControl 的时序参数实现）；如果根本读不到，就是上面两条链路或显示器设置的问题。
  4. 确认这台显示器支持 DDC/CI。 便宜的老显示器、部分电视、以及绝大多数通过 HDMI 接入的屏幕都不支持。 这种情况没有软件层面的办法。

亮度突然调不动了，或者说「显示器未应答（空报文）」

这是 DDC 通道被密集写入写死了 —— 显示器还在正常工作，只是它的 DDC 控制器停止应答请求了。

1.0.1 起不需要你动手：读写一旦无应答，应用会自动重建一次 DDC 通道并重试， 重建相当于热插拔时系统自己做的事，比给显示器断电温和得多，也快得多。 如果你在旧版本上遇到，用下面这个办法自救，一般一次就好，不需要拔线、不需要断电：

  1. 在菜单里展开那台显示器，点「关闭此显示器」。
  2. 它会被移到菜单底部，点那行「（已关闭，点击重新打开）」把它打开。

如果上面这招不管用，再考虑给显示器彻底断电几十秒（拔电源，不是拔视频线 —— 拔线没用， I²C 控制器在 Mac 这一侧）。

这个应用已经尽量在避免这件事

写入节流（外接屏最少间隔 0.1 秒）、读取节流（最少间隔 2 秒）、失败后自动冷却 20 秒、 失败时自动重建通道并重试 —— 都是为了让通道别被写死。但极端情况下仍然可能触发， 所以留了上面这个一键自救的办法。

显示器睡眠 / 唤醒之后，亮度滑块没反应了

这是 1.0.1 修掉的主要 bug 之一，原因很反直觉：显示器睡眠唤醒之后， DDC/CI 的 I²C 通道会「哑掉」 —— 句柄还在、调用也不报错，但读不出也写不进。 在 1.0.1 之前，这个状态会被几处细节卡死（唤醒瞬间重新枚举服务失败会把句柄列表清空、 失败冷却会把写入一起挡掉），于是滑块虽然还在，拖了却纹丝不动。

现在会自动恢复：应用监听系统的唤醒与屏幕配置变化通知，唤醒后会自己重建 DDC 通道； 即使通知漏了，下一次读写失败也会触发同样的自愈。你不需要做任何操作， 菜单里的「重新检测 DDC」现在只是手动兜底。

如果唤醒后滑块那一行显示红色的「无应答」，说明这一次自愈没成功（例如显示器真的死机了）。 展开那台显示器点一次「重新检测 DDC」；再不行就给它断电重启。

打开一台已关闭的显示器之后，菜单里还显示「点击重新打开」

这也是 1.0.1 修掉的 bug。两个原因叠加在一起：

  • 系统在屏幕睡眠时修改显示配置会返回一个错误码（实测是 1014，而不是表示成功的 0）， 但配置其实已经生效了。旧版本只看这个返回值，就以为「没打开成功」，于是那行入口不删。
  • 显示器重新上线时系统可能给它分配一个新的 displayID， 只按 id 记账的记录就永远清不掉了。

1.0.1 改成以观测结果为准：动作发出去之后轮询在线列表，看显示器是不是真的回来了； 「已关闭」记录还会连 EDID 三要素一起存下来，换 id 也认得出同一台屏。 另外现在会先唤醒屏幕再改配置（屏幕上出现菜单说明人就在机器前）， 并且列表改为以 CoreGraphics 为准 —— 因为 `NSScreen` 在一台屏被重新打开之后实测会滞后 3 秒以上。

关掉的显示器去哪了？怎么开回来

展开菜单，滚到最底部，被关掉的显示器会单独列在那儿，标题是「<显示器名> （已关闭，点击重新打开）」。 点它就回来了。

这些入口记在系统偏好设置里，所以退出应用、甚至重启电脑之后再打开，入口都还在。已经重新上线的显示器对应的入口会被自动清理掉。

为什么重启或睡眠之后，关掉的显示器又自己回来了

因为「关闭显示器」是会话级操作，只对当前这次登录有效。显示器睡眠、屏幕休眠、重启，都会让配置回到系统默认状态。

这是有意的安全网：假如某次关闭导致画面异常，重启一下就能回到全部可见的状态，不至于把自己关在外面。 如果希望它跨重启保持关闭，那是另一个功能（需要写系统级显示配置），目前没有做。

为什么关不掉最后一台显示器

这是故意的。应用会拒绝关闭最后一台还在工作的显示器，并且「嘟」一声提示。

否则你会得到一个没有任何画面、也没法操作的机器，只能靠盲操作或者强关机恢复。

DMG 和 zip 该下哪个

推荐 DMG。双击挂载后会出现一个安装窗口，把左边的 Display Master.app 拖到右边的「应用程序」上就装完了，再点侧栏的推出按钮卸载磁盘 —— 不需要先解压，也不用自己去访达里找应用程序文件夹。

两者的内容完全一样，都是同一个 App。区别只在交付方式：DMG 里的 App 带着完整的代码签名封装， 不会遇到下面那条「解压工具弄丢元数据导致应用已损坏」的问题。

zip 适合不想挂载磁盘映像的场景（比如用脚本自动化安装）。但请用系统自带的「归档实用工具」解压， 或者用命令行 ditto -x -k。

挂在侧栏的磁盘删不掉？

那不是文件，是一块临时的只读磁盘。在访达侧栏里点它右边的推出按钮，或者在桌面上右键它 →「推出」即可。 直接把图标拖进废纸篓也行，效果一样。

下载后提示「应用已损坏，请移到废纸篓」

先别删。几乎都是签名或隔离标记的问题，不是文件真的坏了。 两种原因，对应两种做法：

原因一：解压工具破坏了代码签名

macOS 的 zip 里会夹带一层 ._* 元数据文件。如果解压工具把它们直接铺进了 .app 包里， 签名校验就会失败，系统据此判定「已损坏」。

做法：删掉重新解压，这次用 Finder 双击 zip（走系统自带的「归档实用工具」），或者用命令行：

终端
# ditto 是 macOS 自带的，能正确处理 .app 的元数据
ditto -x -k DisplayMaster-1.0.1.zip .

原因二：文件带着下载隔离标记

从网上下载的文件会被打上 com.apple.quarantine 标记，未签名的应用带着这个标记会被拦。 去掉标记即可：

终端
sudo xattr -dr com.apple.quarantine "/Applications/Display Master.app"

更多细节和另外两种更简单的办法，见安装说明。

为什么不能上架 App Store

因为它调用了 macOS 的私有接口，具体是 CGSConfigureDisplayEnabled（来自 SkyLight 框架）。 「单独关闭某台显示器」这件事没有公开 API 可做，只能用私有符号。

这些符号是用 dlopen / dlsym 在运行时加载的，构建时并不链接任何私有框架。 好处是 Apple 哪天把符号改掉了，应用不会直接启动失败，而是「关屏」这一个功能失效，其它功能照常。

随时可以跑 --selftest 确认这些接口在当前系统上还在不在。

它会不会联网、会不会收集数据

不会。整个应用不包含任何网络请求代码，不需要任何系统权限（没有辅助功能、没有屏幕录制、没有完全磁盘访问）， 也不写任何日志文件。

它唯一在磁盘上留下的东西，是系统偏好设置里一条记录，内容是「你关过哪几台显示器」，用来在菜单底部提供恢复入口。 想清掉它：

终端
defaults delete com.zed.displaymaster 2>/dev/null; echo "已清理"

代码量不大，整个仓库读一遍用不了多久，不放心可以直接看。

在 Intel Mac 上能用吗

能运行，但有一处功能缺失，值得提前说清楚。

发布的是通用二进制，Apple Silicon 和 Intel 都能启动。 开关显示器、分辨率、HiDPI、内置屏亮度这些功能都正常。

外接屏的亮度用不了。 它走的是 IOAVService 这个私有框架， 而该框架只存在于 Apple Silicon。Intel 机器的 DDC 要另走一套 IOI2CInterface，项目里没有实现这部分， 菜单里那台外接屏的亮度位置会显示「亮度不可控」。

另外坦白一句：开发和验证都是在 Apple Silicon + macOS 26.6 上做的，Intel 路径没有实机测试过。 如果你在 Intel 上遇到别的问题，欢迎开 issue说明情况。

接了两台同型号的外接屏，亮度会串吗

目前理论上会有风险，值得说明白：

应用现在是把 DDC 服务按顺序跟显示器配对的。只有一台外接屏时，序号和显示器是一一对应的，没问题。 但如果接了两台同型号的外接屏，正确做法应该是按 EDID（每台屏唯一的那串标识）来配对，这部分还没做。

如果你正好是这种配置并且遇到了亮度串屏，欢迎开个 issue， 把两台屏的 EDID 信息（--selftest 的输出）附上。

关掉显示器会把我正在用的窗口搞乱吗

会重新排列，但不会丢。窗口会像你拔掉那台屏幕的线一样，被移到剩下的显示器上； 重新打开那台屏之后，窗口一般不会自动回到原位，需要自己拖回去。

这正是它跟「盖一层黑」的本质区别 —— 它是真的在改显示布局。用之前建议先处理掉正在进行中的全屏应用。

和 BetterDisplay、MonitorControl 是什么关系

没有代码关系，只是思路参考。三个项目解决的是不同的痛点：

项目特点
Display Master 免费、开源、代码量小。核心就三件事：单独开关屏、亮度、HiDPI / 分辨率
BetterDisplay 功能强大得多（虚拟屏、XDR 亮度、色彩配置……），但「显示器连接/断开」属于付费 Pro 功能
MonitorControl 专注外接屏亮度与音量控制，支持键盘快捷键，成熟稳定

这个项目最初就是为了替代 BetterDisplay 那个付费的「断开显示器」功能， 本应用的 DDC 时序参数也参考了 MonitorControl 的 Arm64DDC 实现。

怎么反馈问题

去 GitHub Issues 开一条。 带上这些信息会快很多：

  • macOS 版本、机器型号（Apple Silicon 还是 Intel）
  • 显示器的品牌型号、用什么线接的、中间有没有扩展坞
  • --selftest 和 --ddc-test 的完整输出
  • 期望的行为，以及实际发生的现象

使用说明

整个应用只有一个菜单。下面按菜单从上到下的顺序，把每一项讲清楚。

入口在哪

启动后，菜单栏右侧会出现一个笔记本电脑轮廓的小图标（单色，会跟随菜单栏明暗自动反色）。 点它展开菜单，没有 Dock 图标，也没有主窗口 —— 它不需要这些。

菜单是每次打开时重新构建的，所以显示器热插拔、分辨率变化、亮度被系统设置改过，菜单里看到的永远是最新状态，不需要手动刷新。

每台显示器占一整块

菜单主体按显示器分组，每台显示器包含两行：

行内容点它会发生什么
第一行 显示器名称 + 当前逻辑分辨率 + 状态标记 悬停展开二级菜单（HiDPI / 分辨率 / 关闭 / DDC）
第二行 亮度滑块 + 百分比 直接拖动调亮度，不用进二级菜单

第一行的信息怎么读

标题形如：

示例
Mi Monitor  —  5120×2880 HiDPI  ·  主屏
Color LCD  —  1512×982 HiDPI  ·  内置 / 主屏
  • 5120×2880 —— 当前逻辑分辨率，也就是系统认为的可用空间大小。
  • HiDPI —— 出现这个标记，说明渲染倍率大于 1，画面是以两倍（或更高）像素密度绘制的，文字更细腻。没有这个标记就是普通渲染。
  • 内置 / 主屏 —— 分别是「笔记本自带屏幕」和「当前主显示器」的标记，可能同时出现。

亮度滑块

滑块范围 0–100%，右边实时显示数值。松手时最后一档数值一定会落到显示器上，不会被丢掉。

两种屏幕走的是两条完全不同的路：

屏幕类型控制方式说明
内置屏（笔记本）系统亮度接口 DisplayServices和用键盘上的亮度键是同一套东西，稳定、瞬间生效
外接屏DDC/CI 协议，走 I²C 总线取决于显示器是否实现了这个协议，见下面的注意事项

为什么拖动时不是每个像素都写一次

密集的 I²C 写入会把部分显示器的 DDC 通道「写死」，之后就不再应答任何请求。所以应用对写入做了节流：

  • 外接屏：最多每 0.1 秒写一次
  • 内置屏：最多每 0.03 秒写一次
  • 读取当前亮度：最多每 2 秒读一次（读取比写入更容易打断显示器）

你拖得再快，中间那些值会被合并掉，但松手时的那一档总是会写进去。这是有意的设计，不是丢帧。

如果某一刻显示器没应答，滑块右边的百分比会就地变成红色的「无应答」。 同时应用会自动重建 DDC 通道再试一次（1.0.1 起），所以大多数情况下你不需要做任何事， 接着拖就行了。

显示「亮度不可控」是怎么回事

滑块位置会出现一行灰字，直接写原因，例如：

  • 「该屏未提供亮度接口」—— 内置屏但系统没暴露亮度控制（少见，一般出现在某些外接显示器被误判成内置时）。
  • 「显示器未应答（空报文）」—— 外接屏的 DDC 通道没响应，通常是显示器本身不支持 DDC/CI，或者通道被之前的密集写入写死了。
  • 「DDC 无应答，冷却中（剩 Ns）」—— 刚失败过，正在冷却，到时间会自动重试。

遇到后两种，看 常见问题里的自救办法。

二级菜单：HiDPI 高清渲染

点显示器第一行展开。第一项就是 HiDPI 开关，前面有勾表示当前正开着。

它的目标是在同一个逻辑分辨率上换渲染倍率，也就是「屏幕空间不变，但画面更清晰」。不过并不是每块屏都有同尺寸的变体：

菜单标题显示含义
HiDPI 高清渲染正常。切换后逻辑分辨率保持不变
HiDPI 高清渲染（将切到 3840×2160）没有同尺寸的变体，点了会连分辨率一起变。标题里提前告诉你切到哪一档
HiDPI 高清渲染（该屏不支持）（灰色）这块屏在这台机器上没有任何 HiDPI 模式可用
为什么第二行那种情况会出现

macOS 只暴露显示器 EDID 里声明过的模式。有些外接屏只提供「2× 渲染 + 一半逻辑分辨率」的组合， 没有「1× 和 2× 同一个逻辑尺寸」这一对，所以没法原地切换。内置 Retina 屏经常就是这种情况。

二级菜单：分辨率

展开会看到一个分辨率列表，当前正在用的那一项前面有勾，HiDPI 的档位会额外标注。

默认只列常用档位。原因是显示器的 EDID 常常把缩放档位按 32 像素的步长枚举出一两百个， 全列出来菜单会长到没法看。折叠掉了多少项，开关的悬浮提示里会写。

列表最下面有「显示所有分辨率」开关，需要翻完整列表时打开它。切换后会收起菜单， 下次打开就是完整列表了。

列出来不代表一定能用

这个列表来自系统报告的模式集合。个别档位切过去可能会黑屏几秒然后自动恢复 —— 系统自己会回滚。真遇到切到某个分辨率后画面异常， 等十几秒，或者用 ⌘ + 亮度键之类的组合盲操作，最坏情况重启一次即可。

二级菜单：关闭此显示器

这一项会真的把这台显示器从桌面布局里移除 —— 窗口会重新排列到剩下的屏幕上，鼠标也过不去， 就像拔了线一样。不是盖一层黑图片那种障眼法。

关掉之后：

  • 该显示器会从菜单主体消失，但会在菜单底部单独列出一行，写着「（已关闭，点击重新打开）」。点一下就回来。
  • 关过哪些屏会记进系统偏好设置，所以即使退出再打开应用，底部那行入口还在。
  • 已经有显示器重新上线后，对应的僵尸入口会被自动清掉，不会越积越多。1.0.1 起判定以「显示器是否真的回来了」为准， 并且记录里连 EDID 一起存着，所以显示器换了 displayID 也认得出同一台屏。
不允许关掉最后一台

如果只剩一台显示器还在工作，这一项会拒绝执行并「嘟」一声。这是防止你把自己关到没有画面的安全网。

二级菜单：重新检测 DDC

只在外接屏上出现。它会丢掉缓存的 DDC 连接句柄、解除失败冷却、重新建立通道。

1.0.1 起这只是一个手动兜底入口。显示器睡眠唤醒、通道哑掉、读写无应答时， 应用都会自己重建通道并重试，不需要你点它。留下来是为了应对自动恢复也没成功的极端情况 （比如显示器真的死机了）。

什么时候值得手动点一次：给显示器断电重启之后，或者换过线、插拔过接口之后，亮度滑块的数值看着不对。

菜单底部的固定项

菜单项作用
重新扫描显示器重新枚举所有显示器，同时重建 DDC 连接。快捷键 ⌘R
关于 Display Master版本号，以及可点击的仓库地址
打开项目主页在浏览器里打开 GitHub 仓库，方便反馈问题
退出 Display Master退出应用。快捷键 ⌘Q

用命令行诊断

界面不好脚本化，所以所有自检都做成了命令行参数。应用本身同时就是这套诊断工具：

终端
APP="/Applications/Display Master.app/Contents/MacOS/DisplayMaster"

# 私有接口是否还能加载、检测到几台显示器、模式与亮度接口状态
"$APP" --selftest

# 不打开菜单，直接把整棵菜单树打印出来（排查菜单项是否正常）
"$APP" --dump-menu

# 只报告 HiDPI 开关会切到哪一档，不做任何改动
"$APP" --hidpi-test

# 真的逐台切换一遍再恢复（会短暂黑屏，属正常）
"$APP" --hidpi-test --apply --all

# 读 → 写 → 复读 → 恢复，验证 DDC 写入是否真的生效
"$APP" --ddc-test

# 模拟快速拖动滑块 100 次，验证节流是否把显示器写死
"$APP" --ddc-storm

# 伪造「通道哑掉」，验证读写能不能自动救回来
"$APP" --ddc-recover-test

# 关掉再打开一台显示器，验证记录会不会正确清掉（默认拿内置屏当靶子）
"$APP" --toggle-test

# 让显示器睡下去再唤醒，验证唤醒后 DDC 通道是否可用
"$APP" --wake-test

各项含义见 从源码构建。

键盘与辅助功能

菜单项都带 VoiceOver 标签，亮度滑块虽然每台屏长得一样，读屏时会念成「<显示器名> 亮度」，不会混淆。

应用没有注册全局快捷键 —— 那需要额外的辅助功能权限。想用键盘调亮度，系统自带的 F1 / F2 只能管主显示器， 外接屏还是得从菜单走。

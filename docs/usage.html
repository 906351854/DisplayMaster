使用说明

整个应用只有一个菜单。下面按菜单从上到下的顺序，把每一项挨个讲一遍。

入口在哪

启动后，菜单栏右侧会出现一个笔记本电脑轮廓的小图标（单色，会跟着菜单栏明暗自动反色）。 点它就展开菜单。没有 Dock 图标，也没有主窗口，它用不上这些。

菜单是每次打开时重新构建的，所以显示器热插拔、分辨率变化、亮度被系统设置改过，菜单里看到的永远是最新状态，不需要手动刷新。

每台显示器一张卡

菜单主体是一排横向并排的显示器卡片：几台屏就几张卡，每张卡自带 亮度、开启、HiDPI 三件套 —— 想调哪台屏，就在它自己那张卡上直接调，不用先进去再退出。

卡片里的位置内容点它会发生什么
最上面 这台屏的缩略图（屏幕 + 支架 / 底座，长宽比跟着真实分辨率走） —
名称行 「内置显示器」「外接显示器 1 / 2 / 3」，主屏多一枚「主显示器」徽章 —
型号 / 规格 系统报告的型号名，下一行是「2560 × 1440 · 60 Hz」 —
亮度 小太阳 + 「亮度」，一条细轨道滑块，右端是百分比 直接拖动调亮度
开启 这台屏的开关 关掉 / 打开这台屏。关掉之后卡片留在原地，拨回去就亮
HiDPI 开关 + 状态标签（HiDPI / 标准 / 不支持） 切换这块屏的渲染倍率
右上角「···」 — 进入这块屏的详情页（分辨率 / 关闭 / DDC / 忘记）

卡片上的信息怎么读

  • 缩略图：笔记本轮廓（带底座和刘海）= 内置屏，显示器轮廓（带支架）= 外接屏。 屏幕长宽比跟着真实分辨率走，接一台带鱼屏一眼就认得出来。
  • 2560 × 1440：当前逻辑分辨率，也就是系统认为能用的空间有多大； 后面跟的是当前刷新率。
  • HiDPI / 标准：开关右边那枚标签说的是这块屏的渲染倍率， 不是分辨率。渲染倍率大于 1 时画面按两倍（或更高）像素密度绘制，文字更细腻。
  • 亮度右端的百分比：这块屏当前的亮度，拖动滑块时跟着实时跳； 写入失败会就地变成「无应答」，同时应用会自动重建 DDC 通道再试一次。
  • 整张卡变灰、开关落在关的位置：这台屏现在被关掉了。卡片还在那一排里， 开关拨回去就亮 —— 关掉的屏也有完整信息，因为关掉的那一刻把分辨率、刷新率、 亮度档位、HiDPI 状态一起抄了一份存下来。

超过 4 台显示器会分页

一页最多放 4 张卡。超过 4 台才开始分页，分页时一页 3 张，卡片两侧出现翻页箭头； 第一页时左箭头是灰的，最后一页时右箭头是灰的。

详情页

点卡片右上角的「···」（点卡片头部任意位置也一样）进入。这一页只讲一台屏， 放的是卡片上摆不下的东西 —— 亮度、开启、HiDPI 已经在卡片上了，这里刻意不再放一遍， 免得同一个开关出现在两处、让人以为是两件事：

  • 顶部是「‹ 返回显示器列表」，点它回主面板。
  • 接着是这台屏的头部卡片：缩略图 + 名称 + 「型号 · 分辨率 · 刷新率」。 亮度不可控时，原因全文也写在这里（卡片上只写得下半句）。
  • 往下依次是 分辨率； 然后是 关闭此显示器（已关掉的屏显示成 重新打开此显示器， 下面再多一项 忘记这台显示器（从列表移除））； 外接屏最后还有一项 重新检测 DDC。
  • 底部保留「关于」「打开项目主页」「退出」，不必先退回主面板。

菜单关闭后再打开（或者从别的地方重新点开图标），总是回到主面板 —— 不会停在某个详情页里让人摸不着头脑。

亮度滑块

滑块范围 0–100%。百分比跟在滑块右端，拖动时跟着实时跳； 松手时最后那一档一定会落到显示器上，不会丢。

两种屏幕走的是两条完全不同的路：

屏幕类型控制方式说明
内置屏（笔记本）系统亮度接口 DisplayServices和用键盘上的亮度键是同一套东西，稳定、瞬间生效
外接屏DDC/CI 协议，走 I²C 总线取决于显示器是否实现了这个协议，见下面的注意事项

为什么拖动时不是每个像素都写一次

密集的 I²C 写入会把部分显示器的 DDC 通道「写死」，之后就不再应答任何请求。所以应用对写入做了节流：

  • 外接屏：最多每 0.1 秒写一次
  • 内置屏：最多每 0.03 秒写一次
  • 读取当前亮度：最多每 2 秒读一次（读取比写入更容易打断显示器）

你拖得再快，中间那些值都会被合并掉，但松手时的那一档总是会写进去。这是有意做成这样的，不是漏掉了。

要是某一刻显示器没应答，滑块右端的百分比会就地变成「无应答」， 同时应用会自动重建 DDC 通道再试一次（1.0.1 起）。大多数情况下你什么都不用做，接着拖就行。

显示「亮度不可控」是怎么回事

这时卡片上本该是滑块的位置会直接写出原因（一行放不下就省略），全文在详情页里，比如：

  • 「该屏未提供亮度接口」：内置屏，但系统没有暴露亮度控制。这种情况少见，一般出现在某些外接显示器被误判成内置的时候。
  • 「显示器未应答（空报文）」：外接屏的 DDC 通道没响应，通常是显示器本身不支持 DDC/CI，或者通道被之前密集的写入写死了。
  • 「DDC 无应答，冷却中（剩 Ns）」：刚失败过，正在冷却，时间到了会自己重试。

遇到后两种，看 常见问题里的自救办法。

卡片上的 HiDPI 开关

每张卡最后一行就是 HiDPI：左边一个开关，右边一枚标签告诉你现在的状态。

卡片上的样子含义
开关开着，标签是蓝色 HiDPI正跑在 2×（或更高）渲染倍率上
开关关着，标签是灰色 标准这块屏支持 HiDPI，现在跑的是 1× 渲染
开关灰掉打不开，标签写着 不支持这块屏在这台机器上没有任何 HiDPI 模式可用
整张卡变灰、开关落在关的位置这台屏被关掉了，标签里写的是它关闭前那一档的状态

它想做到的是在同一个逻辑分辨率上换渲染倍率，屏幕空间不变，画面更清晰。 但正如上面最后两行所示，不是每块屏都能原地切。

有些屏切 HiDPI 会连分辨率一起变

macOS 只暴露显示器 EDID 里声明过的模式。有些外接屏只提供「2× 渲染 + 一半逻辑分辨率」的组合， 没有「1× 和 2× 同一个逻辑尺寸」这一对，所以没法原地切换。内置 Retina 屏经常就是这种情况。

碰到这种屏，开关拨过去会连分辨率一起换掉。宁可用详情页里的 分辨率列表精确挑一档 —— 那里每一档都写得清楚。

详情页：分辨率

详情页里的「分辨率」展开是一个分辨率列表，正在用的那一项前面有勾，HiDPI 的档位会额外标一下。

默认只列常用档位。因为显示器的 EDID 常常按 32 像素的步长枚举出一两百个缩放档位， 全列出来菜单会长得没法看。折叠了多少项，开关的悬浮提示里会写。

列表最下面有「显示所有分辨率」开关，想翻完整列表的时候打开它。切换后菜单会收起来， 下次打开就是完整列表了。

列出来不代表一定能用

这个列表来自系统报告的模式集合。个别档位切过去可能会黑屏几秒再自动恢复，系统自己会回滚。真遇到切到某个分辨率之后画面不对， 等十几秒，或者用 ⌘ + 亮度键之类的组合盲操作一下，最坏也就是重启一次。

关掉一台显示器

两条路都通向同一件事：卡片上的「开启」开关拨到关，或者进详情页点 「关闭此显示器」。它会把显示器真正从桌面布局里摘掉： 窗口重新排到剩下的屏幕上，鼠标也过不去，跟拔了线差不多。它不是在屏幕前面盖一层黑图。

关掉之后：

  • 它不会从那一排卡片里消失，只是整张卡变灰、「开启」落在关的位置上。 想开回来，把「开启」拨回去就行 —— 不用去菜单底部那一堆文字行里翻。
  • 卡片上照样显示「1680 × 1050 · 60 Hz」和关闭前的亮度档位。因为 在关掉它的那一刻，分辨率、刷新率、亮度、HiDPI 状态都抄了一份存下来， 屏都黑了这些值本来就查不到了。
  • 关过哪些屏会记进系统偏好设置，所以即使退出再打开应用，那张卡片还在。
  • 显示器重新上线之后，卡片会自动切回在线状态，记录跟着清掉，不会越积越多。1.0.1 起以 「显示器是不是真的回来了」为准，记录里还连 EDID 一起存着，所以就算换了 displayID， 也认得是同一台屏。
关掉之后又拔了线怎么办

这条记录就永远等不到它回来了 —— 自动清理只认「按 EDID 发现它回来了」。 所以详情页里还有一项「忘记这台显示器（从列表移除）」，用来手动收尾。 随航 / 隔空播放投出来的临时屏（iPad 一断开就回不来的那种）不会被记进去。 时间长了记不清哪些是临时屏也没关系：那些卡片一眼就能认出来，因为是灰的。

不允许关掉最后一台

如果只剩一台显示器还在工作，这一项会拒绝执行，然后「嘟」一声。总得给你留一条能看见画面的路。

详情页：重新检测 DDC

只在外接屏上出现。它会丢掉缓存的 DDC 连接句柄、解除失败冷却、重新建立通道。

1.0.1 起它只是个手动兜底入口。显示器睡眠唤醒、通道哑掉、读写无应答的时候， 应用都会自己重建通道再试一次，不用你动手。留着它，是为了应付自动恢复也没成功的极端情况， 比如显示器真的死机了。

什么时候值得手动点一下：给显示器断电重启之后，或者换过线、插拔过接口之后，亮度滑块上的数值看着不对。

主面板：有外接屏时自动关闭内置屏

笔记本接着外接显示器的时候，不少人其实只想用外接那块屏。菜单里有一项开关就是干这个的： 有外接屏时自动关闭内置屏。

打开之后，插上外接屏，笔记本内屏会自动关掉（和详情页里点「关闭此显示器」是同一件事， 不是盖一层黑图）。拔掉外接屏，内屏再自己亮回来。

它什么时候动手，什么时候不动

只在外接屏「接上」和「拔掉」这两个瞬间做事。中间你要是手动把内屏开回来干点活， 它不会立刻又给你关掉，下一次插拔才会重新判断。这是特意这么做的， 否则这个开关就会一直跟你较劲。

屏幕正在睡眠时它什么都不做 —— 睡眠状态下系统不接受改显示配置，硬来还会把屏幕平白唤醒。

系统会自己造一块看不见的屏幕

内屏关着、外接屏也拔掉之后，macOS 会造一台虚拟显示器来维持显示输出 —— 它没有任何物理输出，你也看不到它。麻烦在于它的身份看起来跟外接屏一样（ CGDisplayIsBuiltin 返回 0），应用要是把它算成「外接屏还在」， 这条规则就永远不会动手，而你面对的是一块黑屏。

1.1.1 起会把它认出来并排除：菜单里不出现，所有判断里也不算数。所以这个开关在你看来 就是干脆的「外接屏一拔，内屏立刻亮」，中间系统多了什么都不用管。

出问题了怎么查

这个功能失效的样子是黑屏，而黑屏的时候你没法打开菜单，所以每次判断都会落一份日志：

"$APP" --auto-log

它打印的是判断现场 —— 收到配置变化时在线的是什么、判定成什么、执行成没成、有没有重试。 反馈问题的时候把它贴出来，就能看出卡在哪一步。

拔掉外接屏之后，内屏一定会亮回来

内屏关着、外接屏又拔了，这时候如果没人去开它，你面对的就是一块黑屏。 所以规则里这一条写得最死：只要外接屏一个都不在，内屏就必须在。

开关是记住的，但「关掉了哪块屏」不是

这个开关本身会一直记着，重启也还在。但具体「内屏关着」这个状态只对本次登录有效 —— 重启或者显示睡眠之后系统会把它恢复。所以重启完你可能看到内屏又亮了， 过一会儿规则会再判断一次，该关的话会重新关掉。

菜单项作用

用命令行诊断

界面上的东西不好脚本化，所以自检全做成了命令行参数。应用本身同时也是这套诊断工具：

终端
APP="/Applications/Display Master.app/Contents/MacOS/DisplayMaster"

# 私有接口是否还能加载、检测到几台显示器、模式与亮度接口状态
"$APP" --selftest

# 不打开菜单，直接把整棵菜单树打印出来（排查菜单项是否正常）
"$APP" --dump-menu

# 只报告 HiDPI 开关会切到哪一档，不做任何改动
"$APP" --hidpi-test

# 真的逐台切换一遍再恢复（会短暂黑屏，属正常）
"$APP" --hidpi-test --apply --all

# 读 → 写 → 复读 → 恢复，验证 DDC 写入是否真的生效
"$APP" --ddc-test

# 模拟快速拖动滑块 100 次，验证节流是否把显示器写死
"$APP" --ddc-storm

# 伪造「通道哑掉」，验证读写能不能自动救回来
"$APP" --ddc-recover-test

# 关掉再打开一台显示器，验证记录会不会正确清掉（默认拿内置屏当靶子）
"$APP" --toggle-test

# 让显示器睡下去再唤醒，验证唤醒后 DDC 通道是否可用
"$APP" --wake-test

# 报告「有外接屏时自动关内屏」这一轮会做什么判断（加 --apply 才真的执行）
"$APP" --auto-test

# 用构造出来的场景跑一遍判定逻辑，不接触真实显示器
"$APP" --auto-scenarios

# 把真实菜单弹出来截图，核对卡片外观；--fake-off 0,2 把第 0、2 张卡画成已关闭
"$APP" --shot-menu /tmp/menu.png --fake-cards 3 --fake-off 2

# 模拟点击某张卡：--click-part dots|on|hidpi 指定点它的哪个部位
"$APP" --shot-menu /tmp/menu.png --click-card 0 --click-part hidpi

# 把每张卡里「··· / 开启 / HiDPI」各自占的屏幕坐标打出来（合成点击时用来精确命中）
"$APP" --hits

# 直接开 / 关一台显示器，验证「关掉的屏留在卡片排里」这条链路
"$APP" --display-off 2

# 报告并真的切一次 HiDPI，验证「菜单收尾之后再动手」这件事
"$APP" --hidpi-toggle 2

各项含义见 从源码构建。

键盘与辅助功能

菜单项都带 VoiceOver 标签。亮度滑块每台屏长得一样，但读屏时会念成「<显示器名> 亮度」，不会听混。

应用没有注册全局快捷键，那需要额外的辅助功能权限。想用键盘调亮度的话，系统的 F1 / F2 只管得了主显示器， 外接屏还是得从菜单里拖。

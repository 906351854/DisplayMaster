安装

两条路：下载打包好的 App（一分钟搞定），或者自己从源码编译。第一次打开会被 macOS 拦一下，这是正常的， 下面有专门的说明。

先看系统要求

项目要求
系统版本macOS 14（Sonoma）或更高
处理器通用二进制，Apple Silicon 与 Intel 均可运行（Intel 上有一处功能限制，见下方说明）
磁盘占用不到 5 MB
附加依赖无。不需要 Xcode、不需要装任何运行时
开发验证环境macOS 26.6 (Tahoe) + Apple Silicon
Intel Mac 上外接屏亮度用不了

外接屏亮度走的是 IOAVService 这个私有框架，而它只存在于 Apple Silicon。 Intel 机器的 DDC 走另一套 IOI2CInterface，本项目没有实现。

所以 Intel 上：开关显示器、分辨率、HiDPI、内置屏亮度都正常，只有外接屏的亮度滑块会显示「亮度不可控」。 另外要说明的是，开发和验证都是在 Apple Silicon + macOS 26.6 上完成的，Intel 路径没有实测过 —— 如果你在 Intel 上遇到问题，欢迎反馈。

它用了 macOS 的私有接口

「单独关闭某台显示器」这件事没有公开 API，只能调用系统的私有接口。所以 这个应用无法上架 App Store， 而且 Apple 有可能在未来的系统版本里改掉这些接口。仓库里的 --selftest 命令可以随时检查接口是否还在。

方法一：下载 DMG 安装包（推荐）

去 Releases 页面 下载最新的 .dmg，然后：

  1. 双击 DMG。系统会把它挂成一个叫 Display Master 的磁盘，并弹出安装窗口。
  2. 把左边的 App 图标拖到右边的「应用程序」上。那个「应用程序」图标其实就是指向系统应用程序文件夹的快捷方式， 拖过去等于装好了 —— 这一步专门做过，省得你再去访达里找目录。
  3. 推出磁盘。在访达侧栏点那个磁盘右边的推出按钮，或者在桌面上右键它选「推出」。
  4. 第一次打开要绕一下 Gatekeeper，见下一节。
为什么 DMG 比 zip 好

DMG 里的 App 带着完整的代码签名封装，不存在「解压工具把签名元数据弄丢、系统报应用已损坏」这种问题 —— 直接双击打开就能拖，少一步解压，也少一类坑。这也是 macOS 上分发应用最常见的形式。

方法二：下载 zip 包

不想挂载磁盘映像的话，同一个 Release 里也放了 .zip：

  1. 解压。双击 zip 就行，macOS 自带的「归档实用工具」会正确处理。
    注意：不要用某些第三方解压软件。App 的代码签名依赖 zip 里的一层元数据，个别解压工具会丢掉它，导致系统报「应用已损坏」。
  2. 拖进「应用程序」。把解压出来的 Display Master.app 拖到「访达 → 应用程序」里。
  3. 第一次打开要绕一下 Gatekeeper，见下一节。

第一次打开：绕过 Gatekeeper

双击应用时大概率会看到「无法打开，因为 Apple 无法检查其是否包含恶意软件」，或者更吓人的「应用已损坏，请移到废纸篓」。

这不是文件坏了，也不是下载出错。 原因很简单：这个应用没有花钱买 Apple 开发者签名， 系统对「来源不明的应用」一律拦下。下面三种办法任选一种，做一次就够了。

办法 A：右键打开（最省事）

  1. 在「应用程序」里找到 Display Master。
  2. 按住 Control 键点它（或者直接右键），选「打开」。
  3. 弹出的对话框里还会有一个「打开」按钮，再点一次。

之后正常双击就能启动了。这一步只需要做一次，系统会记住你的选择。

办法 B：从系统设置里放行

  1. 先双击应用一次，让它被拦下。
  2. 打开「系统设置 → 隐私与安全性」。
  3. 往下滚到「安全性」区域，会看到一行「已阻止使用「Display Master」，因为来自身份不明的开发者」。
  4. 点旁边的「仍要打开」，再输入密码确认。

办法 C：用命令行去掉隔离标记

从网上下载的文件会被打上 com.apple.quarantine 标记，防火墙就是根据它来拦的。把标记去掉即可：

终端
# 去掉隔离标记（需要输入密码，因为改的是「应用程序」目录）
sudo xattr -dr com.apple.quarantine "/Applications/Display Master.app"

# 顺便确认一下签名状态，看 rejected 是正常的（自签名应用都这样）
spctl -a -vv "/Applications/Display Master.app"
spctl 报 rejected 并不是出错了

这个命令是拿 Apple 的官方签名数据库来检验的，任何自己编译或自签名的应用都会返回 rejected。 它只能说明「不是 Apple 认证的开发者签的」，不代表文件有问题。想确认完整性，看代码本身更实在 —— 整个仓库读一遍用不了多久。

方法三：从源码编译

如果你不放心下载二进制，或者想改点东西，直接编译。需要先装 Xcode 命令行工具：

终端
# 只装命令行工具就够了，不用装完整的 Xcode
xcode-select --install

# 克隆并构建
git clone https://github.com/906351854/DisplayMaster.git
cd DisplayMaster
./build.sh

脚本会自动完成：编译 release 版本 → 组装 .app 目录结构 → 做 ad-hoc 签名 → 装到 /Applications → 重启正在运行的实例。加 --no-install 则只产出到 build/ 目录，不动系统里的。

自己编译出来的 App 没有下载隔离标记，所以不会有 Gatekeeper 弹窗，直接就能跑。

确认装好了

启动后菜单栏右侧会出现一个笔记本电脑形状的小图标，桌面上不会多出窗口，Dock 里也不会多出图标 —— 这是有意设计的，它就是个纯菜单栏工具。

想更确定一点，可以跑一次自检：

终端
"/Applications/Display Master.app/Contents/MacOS/DisplayMaster" --selftest

它会逐项报告：私有接口能不能加载、检测到几台显示器、每台的分辨率模式、亮度接口是否可用。想了解各项的含义，看 从源码构建里的命令行说明。

让它开机自动启动

应用本身没有做自启开关（那需要额外的系统权限），用系统自带的功能就好：

  1. 打开「系统设置 → 通用 → 登录项与扩展」。
  2. 在「登录时打开」一栏点 +。
  3. 选择「应用程序」里的 Display Master，点「添加」。

卸载

退出应用（菜单里选「退出 Display Master」），然后把 /Applications/Display Master.app 拖进废纸篓。

它会在系统的偏好设置里留下一条记录，用来记住你关过哪几台显示器。想彻底清掉：

终端
defaults delete com.zed.displaymaster 2>/dev/null; echo "已清理"

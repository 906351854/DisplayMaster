安装

你可以直接下载打包好的应用，也可以自己从源码编译，两条路都行。第一次打开会被 macOS 拦一下， 这是正常现象，下面单独讲怎么处理。

先看看系统要求

项目要求
系统版本macOS 12（Monterey）或更高
处理器通用二进制，Apple Silicon 和 Intel 都能跑（Intel 上有一处限制，下面会说到）
磁盘占用不到 5 MB
附加依赖没有。不用装 Xcode，也不用装任何运行时
开发验证环境macOS 26.6 (Tahoe) + Apple Silicon
Intel Mac 上外接屏亮度用不了

外接屏的亮度靠 IOAVService 这个私有框架，而它只存在于 Apple Silicon。 Intel 机器要走另一套 IOI2CInterface，这部分没有实现。

所以 Intel 上，开关显示器、分辨率、HiDPI、内置屏亮度都是正常的，只有外接屏那一格会写「亮度不可控」。 还得说一句，开发和验证都是在 Apple Silicon + macOS 26.6 上做的，Intel 那边没有实机跑过。要是你在 Intel 上遇到问题，欢迎来反馈。

它用了 macOS 的私有接口

macOS 没有提供「单独关闭某台显示器」的公开 API，所以只能用私有接口。这也意味着它上不了 App Store， 而且 Apple 以后如果改动这些接口，这个功能可能会失效。随时可以跑一下 --selftest，看看接口还在不在。

方法一：下载 DMG 安装包（推荐）

去 Releases 页面 下载最新的 .dmg，然后：

  1. 双击 DMG。系统会把它挂成一个叫 Display Master 的磁盘，并弹出安装窗口。
  2. 把左边的 App 图标拖到右边的「应用程序」上。右边那个「应用程序」是指向系统应用程序文件夹的快捷方式， 拖过去就等于装好了。
  3. 推出磁盘。在访达侧栏点那个磁盘右边的推出按钮，或者在桌面上右键它选「推出」。
  4. 第一次打开要绕一下 Gatekeeper，见下一节。
为什么 DMG 比 zip 好

DMG 里的 App 带着完整的代码签名，不会遇到「解压工具弄丢元数据、系统说应用已损坏」这类问题。 双击打开就能拖，少一步解压。macOS 上分发应用一般也是这个形式。

方法二：下载 zip 包

不想挂载磁盘映像的话，同一个 Release 里也放了 .zip：

  1. 解压。双击 zip 就行，macOS 自带的「归档实用工具」会正确处理。
    建议别用第三方解压工具。代码签名依赖 zip 里的一层隐藏元数据，有些工具会把它弄丢，系统就会报「应用已损坏」。
  2. 拖进「应用程序」。把解压出来的 Display Master.app 拖到「访达 → 应用程序」里。
  3. 第一次打开要绕一下 Gatekeeper，见下一节。

第一次打开：绕过 Gatekeeper

双击应用时，多半会看到「无法打开，因为 Apple 无法检查其是否包含恶意软件」，偶尔还会跳一句更吓人的「应用已损坏，请移到废纸篓」。

文件没有坏，下载也没出错。 只是因为它没有花钱买 Apple 开发者签名，系统对这类应用会一律拦下来。 下面三种办法挑一种做就行，做过一次就够。

办法 A：右键打开（最省事）

  1. 在「应用程序」里找到 Display Master。
  2. 按住 Control 键点它（或者直接右键），选「打开」。
  3. 弹出的对话框里还会有一个「打开」按钮，再点一次。

之后正常双击就能启动了。这一步只需要做一次，系统会记住你的选择。

办法 B：从系统设置里放行

  1. 先双击应用一次，让它被拦下。
  2. 打开「系统设置 → 隐私与安全性」。
  3. 往下滚到「安全性」区域，会看到一行「已阻止使用「Display Master」，因为来自身份不明的开发者」。
  4. 点旁边的「仍要打开」，再输入密码确认。

办法 C：用命令行去掉隔离标记

从网上下载的文件会被打上 com.apple.quarantine 标记，防火墙就是根据它来拦的。把标记去掉即可：

终端
# 去掉隔离标记（需要输入密码，因为改的是「应用程序」目录）
sudo xattr -dr com.apple.quarantine "/Applications/Display Master.app"

# 顺便确认一下签名状态，看 rejected 是正常的（自签名应用都这样）
spctl -a -vv "/Applications/Display Master.app"
spctl 报 rejected 并不是出错了

这个命令查的是 Apple 的官方签名数据库，自己编译或者自签名的应用都会返回 rejected。 它只说明「不是 Apple 认证开发者签的」，不代表文件有问题。真想知道它干不干净，读代码比看签名有用。

方法三：从源码编译

不放心二进制文件，或者想改点什么，那就自己编译。先装一下 Xcode 命令行工具：

终端
# 只装命令行工具就够了，不用装完整的 Xcode
xcode-select --install

# 克隆并构建
git clone https://github.com/906351854/DisplayMaster.git
cd DisplayMaster
./build.sh

脚本会一路做完：编译 release 版本 → 组装 .app 目录结构 → 做 ad-hoc 签名 → 装到 /Applications → 重启正在运行的实例。加 --no-install 则只产出到 build/ 目录，不动系统里的。

自己编译出来的 App 不带下载隔离标记，所以不会有 Gatekeeper 弹窗，直接就能跑。

确认装好了

启动后，菜单栏右侧会多出一个笔记本电脑形状的小图标，不会弹窗口，Dock 里也不会多出图标。 它本来就是个只在菜单栏里待着的工具。

想更确定一点，可以跑一次自检：

终端
"/Applications/Display Master.app/Contents/MacOS/DisplayMaster" --selftest

它会一项项报给你：私有接口能不能加载、检测到几台显示器、每台的分辨率模式、亮度接口可不可以用。想弄明白每一项的含义，看 从源码构建里的命令行说明。

让它开机自动启动

应用第一次运行时会自己注册两个 launchd 服务 （~/Library/LaunchAgents/com.zed.displaymaster.plist 和 com.zed.displaymaster.rescue.plist），登录时自动启动就是它们带的效果， 不用再去系统设置里手动添加。

这两个服务还管可靠性：GUI 应用崩溃或被杀时，launchd 几秒内把它拉起来； 另有一个无界面的救援守护常驻，就算 GUI 整个不在了，拔掉显示线内屏也会被它点亮 （详见 FAQ）。从菜单里正常退出 GUI 不会被强行拉活，退出就是退出； 不想让它开机自启的话，删掉那两个 plist 文件即可。

当然也可以用系统自带的方式（效果和上面等价，二选一就行）：

  1. 打开「系统设置 → 通用 → 登录项与扩展」。
  2. 在「登录时打开」一栏点 +。
  3. 选择「应用程序」里的 Display Master，点「添加」。

卸载

退出应用（菜单里选「退出 Display Master」），然后把 /Applications/Display Master.app 拖进废纸篓。

它会在系统偏好设置里留一条记录，记着你关过哪几台显示器；两个 launchd 服务 也会各留一个 plist。想连它们一起清掉：

终端
launchctl bootout gui/$(id -u)/com.zed.displaymaster 2>/dev/null
launchctl bootout gui/$(id -u)/com.zed.displaymaster.rescue 2>/dev/null
rm -f ~/Library/LaunchAgents/com.zed.displaymaster*.plist
defaults delete com.zed.displaymaster 2>/dev/null; echo "已清理"
